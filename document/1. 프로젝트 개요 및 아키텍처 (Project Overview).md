# 📄 문서 1: 프로젝트 개요 및 아키텍처 (Project Overview)
## 1. 프로젝트명
Abliteration Research Dashboard (ARD): 다차원 투영 기반 LLM 탈옥 및 데이터 무결성 최적화 분석 도구

## 2. 개발 개요
본 프로젝트는 LLM(Llama-3-8B) 내부의 거절 매커니즘을 수학적으로 제거(Abliteration)하는 연구를 지원하기 위한 실험용 대시보드 개발을 목적으로 한다. 사용자는 웹 UI를 통해 실시간으로 수술 파라미터를 조절하고, 대량의 질문 셋을 실행하여 **'탈옥 성공률'**과 '데이터 무결성' 간의 최적의 지점을 찾아낸다.

## 3. 기술 스택 (Tech Stack)
- Language: Python 3.10+
- Model Framework: `transformer_lens` (Hooking & Intervention)
- UI Framework: `Streamlit` (Rapid Prototyping & Data Table Editing)
- Math/Stats: `PyTorch`, `Scikit-learn` (PCA), `NumPy`
- GPU 런타임: **Google Colab (Pro 권장, L4 22GB / A100 40GB)**. Llama-3-8B를
  `transformer_lens`로 로드 + FP32 hook 연산까지 감당하려면 24GB급 GPU가 필요하다.
  Colab 무료 T4(16GB)는 로딩 중 OOM 위험이 크다.
- OCI A1 인스턴스: **GPU 없음**(ARM CPU, 24GB는 시스템 RAM). 대시보드/코드 편집·
  경량 작업만 담당하고, 모델 추론은 Colab에서 실행한다.

## 4. 시스템 아키텍처
Core Engine: `transformer_lens`를 이용한 모델 로드 및 Subspace Projection 집도.
실행 위치: 모델을 로드하는 모든 경로(거절 벡터 스캔·실시간 수술·전수 조사)는
Colab GPU 런타임에서 동작한다. Streamlit 앱 자체를 Colab에서 띄우고
터널(`cloudflared`/localtunnel)로 노출하거나, 배치 작업(탭 A·C)은 노트북 셀로
실행한다. 상세 운영 지침은 문서 5 §8.
State Management: Streamlit 세션 상태를 이용한 실험 데이터 및 모델 캐싱.
Data Layer: 실험 결과 CSV는 Google Drive에 저장(런타임이 휘발성이므로).
